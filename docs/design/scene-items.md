# Scene items (owner, 2026-11-08)

**What this holds:** Scene items (owner, 2026-11-08). Moved from the overall plan (`CESIUM2_WEBGPU_PLAN.md`) on 2026-11-13, with its content and dates unchanged.

**Decided, in its small version, in plan 5a Task 20.** The API separates content from being in the scene. `engine.loadTileset(url)` gives the content (tree, selection, cache), and `world.add(tileset, { placement, opacity, tint, viewMask })` gives a `SceneItem`: that content placed in a world, with its own appearance. A tileset can have several items, with one selection and one cache. This replaces the working name "presentation", which reads as the swap chain's present to a graphics programmer.

**Not a scene graph.** Items are a flat list in a world, with no tree walked per tick, since GPU-driven drawing wants flat records. Hierarchy stays with the reference frame tree: an item attaches to a reference frame or anchor.

The owner leans toward following USD's concepts, anticipating a possible convergence of USD with 3D Tiles and glTF: read USD's model of prims, references, payloads and composition, and today's OpenUSD and glTF interoperability work, before settling names and structure. Also read glTF 2.1, in development in the open at Khronos (tracking issue `KhronosGroup/glTF#2585`, read 2026-11-08; explainers, with schema and normative text still to come). A node can reference an external glTF or GLB, loaded once and instantiated many times; bounding volumes on nodes can drive deferred loading; streaming and level of detail aren't defined in its core, and it cites 3D Tiles' extensions for those. So an item's content could be one glTF that refers to others, and 3D Tiles and external assets overlap on loading content on demand. Khronos calls it complementary to OpenUSD.
