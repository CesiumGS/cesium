# For a later brainstorm: editing (owner, 2026-11-08)

**What this holds:** For a later brainstorm: editing (owner, 2026-11-08). Moved from the overall plan (`CESIUM2_WEBGPU_PLAN.md`) on 2026-11-13, with its content and dates unchanged.

Not designed. A question to take up in its own session, then add to this plan: editing use cases, and how the engine can efficiently support things like CAD-style mesh editing or b-rep-based solid modeling. Today's content is streamed, immutable and tiled, so questions include how edited geometry coexists with tiles, how often buffers change, and where a modeling kernel would sit relative to the engine's seams. Related: geometry submission and per-draw constants (the seams), snapping and measurement, the later tessellation engine ([bodies-frames-and-engineering-coordinates.md](bodies-frames-and-engineering-coordinates.md)), and design space (plan 5f).

**Vector data and GIS sources (owner, 2026-11-08).** Part of the same brainstorm, for the vector rendering engine. Vector data commonly comes from databases such as PostGIS and similar. How would editing vectors interact with the engine, with ion and with 3D Tiles? The same question applies to MVT servers that stream, to WMS, and to the other common GIS streaming protocols: which of them the engine should read, what happens to an edit when the data is tiled or served by someone else, and how updates reach a view that's already drawing them.
