`test/volumes.test.ts` imports 1.x's `TileBoundingRegion`, which imports `packages/engine/Source/Shaders/**/*.js`. Those modules are generated by the repository's `gulp build` and aren't committed, so in a fresh worktree (and in CI, CS-361) the file fails to load: one failed test file in an otherwise clean `npm test`. Seen in every fresh worktree since the tracker's branch (2026-11-13) and again on `dyno-work-ui` (2026-11-14).

Options:

- **Build what the test needs.** A setup step (or a vitest global setup) that runs only the shader-module generation when the modules are missing. Cost: a 1.x build step in `packages/next`'s tests.
- **Skip with the precondition.** The test checks for the generated modules and skips, saying which command makes them. Cost: the test doesn't run where nobody has built 1.x, which is most worktrees.
- **Fold it into worktree setup.** A worktree setup command (links `node_modules`, finds the ion token as CS-413 decides, generates the shader modules) so every worktree starts complete.

Recommendation: the first, run only when the modules are missing; the third is worth doing anyway. CS-399's reporter records the test as environment-only until then.

Progress (2026-11-15): `env.worktree_setup` in `.human-in-the-lead/policy.json` (004c72a98a) installs and builds 1.x in every worktree hitld makes, so a fresh worktree of that kind runs `npm test` clean (342 files, 5338 tests). A worktree made by hand or by the harness, and CI, still need it. CS-541 (the oracle pinned to CesiumJS 1.147.0) would remove the 1.x build altogether.
